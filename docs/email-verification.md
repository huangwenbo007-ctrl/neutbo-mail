# 邮箱验证码注册：测试与发布

## 已实现

普通注册和第三方账号首次绑定均要求验证已有外部邮箱。验证码是随机六位数字，5 分钟有效；同一邮箱每 60 秒可重发，每个 IP 每小时最多 10 次发送请求，每个验证码最多尝试 5 次。重发使旧验证码失效。邀请码和普通注册原有的 Turnstile 校验继续生效。

KV 只保存有过期时间的验证码 HMAC 摘要。D1 负责频率、尝试次数和原子消费；重复或并发使用只能成功一次。验证码消费后如果后续创建账号失败，需要重新发送验证码。

## 本地测试

在 `mail-worker` 中运行 `pnpm test`。测试只使用本地独立 D1/KV，Resend 和 Turnstile 的外部请求使用模拟响应，不会投递真实邮件。原来的部署测试命令已明确更名为 `pnpm deploy:test`，不要用它代替自动化测试。

## Cloudflare 预览

构建 #65c9bd76 失败的原因是配置中的 Worker 名称 `cloud-mail` 与账户内的 `neutbo-mail` 不一致（10007）。配置现已修正，并更新 Wrangler 以支持当前预览功能。

本次新建、仅用于测试的资源：

- D1：`neutbo-mail-verification-test`，ID `2eebad0f-ffe7-4347-b55e-c9f74b7aad2c`
- KV：`neutbo-mail-verification-test-kv`，ID `f72aeaa4a60847c984160f99de6c4e1e`

`wrangler.toml` 的 `previews` 配置明确使用以上资源。预览不应绑定生产数据库 `neutbo-mail` 或 KV `neutbo-mail-kv`，也不要导入生产邮件触发器。多个分支预览共用这套测试存储，应串行测试。

预览上线后仍需要在预览环境中单独配置 `jwt_secret`，初始化测试数据库，并在测试邮箱管理界面配置 Resend。不要把密钥提交到 GitHub 或粘贴到聊天中。发送地址默认采用已配置 Resend Token 的第一个域名下的 `no-reply@域名`，需要确认 Resend 已验证该域名且密钥允许发件。

## 发布前必做

1. 在 Cloudflare 检查预览部署实际绑定的资源确为上述测试资源。
2. 在预览完成真实邮件投递、输入验证码、注册、登录及第三方首次绑定测试。
3. 在正式切换流量前创建验证码使用的两张表；项目初始化入口包含建表逻辑。GitHub Actions 的现有工作流在部署后调用初始化，而 Cloudflare 原生 Git 构建不会自动调用该入口，不能仅凭构建成功就视为数据库已更新。
4. 确认生产 D1/KV 备份和回退方案，再批准生产部署。

合并至 `main` 会触发现有自动部署。草稿 PR 通过以上检查前不要合并。本次测试不证明垃圾邮件识别、邮件投递信誉或 Gmail 级别的服务能力。
